# backlog

The queue. The pair loop takes a ripe Flight first, then the first ripe Issue in running order. `ORDER` ranks Flights and standalone Issues, one slug per line: the developer's above `# groomed below`, and below it those `just groom` placed. The rest follow in filename order. A part, an Issue whose `parent:` names a Flight in this directory, has no line of its own: it runs where its Flight's line is, after any sibling its `waits_on` names and otherwise in filename order, and the Flight's check comes after its parts. A part whose Flight has left this directory stands alone and keeps a line. An Issue is ripe when its `waits_on` Issues are all done and it has no `Needs elaboration` section; a Flight, an Issue others name in `parent:`, is ripe once every one of them is in `done/` as well. `just groom` grooms each Issue here that has no `difficulty` and no `Needs elaboration` section, and places each new Flight and standalone Issue below the marker without moving the rest; `just pair` takes the order as it stands. The loop sends an Issue back here, with that section, when it cannot be done as written.
